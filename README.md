# 茶叶拼配审评台

审评员对一个拼配批次打香气、滋味、汤色。服务端按 0.3 / 0.5 / 0.2 加权，7 分及以上通过。提交后只替换表格里新的一行，不整页跳转。

## 审评台与批次调拨

顶栏「调拨台」进入调拨台专页，含三段：

1. **台名册**：维护审评台，台名唯一（重复登记返回 400）。观察员可看，不能登台。
2. **发起调拨**：在两台之间调拨批次，调拨单含源台、目标台、批次、调拨人、时刻。源/目标台下拉只来自名册；未入册的台名（无论源还是目标）服务端直接拒收且履历不增。
3. **调拨履历**：调拨成功后写入 `transfers`，PostgreSQL 触发器禁止 UPDATE / DELETE，不可删改。

**服务端台过滤**：总表顶栏按台过滤，归属完全在数据库端计算——取每批最新一条调拨履历的目标台。调走后源台视图在服务端就查不到该批最新行（不是浏览器本地藏行），目标台视图查得到；未入册台名的过滤请求返回 400。

**权限**：taster（审评员）可登台、可建调拨单、可审评；observer（观察员）只能看台名册、履历与总表，不能登台、不能建调拨单（POST 返回 403）。

这是制茶审评，不是菜谱，也不是饮食记录。

## 验收

1. taster 登录后看到春茶-A 通过、夏茶-C 不通过。
2. 再提交一组高分，新行出现在表头，页面不整页刷新。
3. observer 登录后没有提交表单，调拨台页提示只读，POST `/stations`、`/transfers` 均 403。
4. 调拨台页登记「甲台」「乙台」（重复登记甲台返回 400）。
5. 发起调拨：源台甲台、目标台乙台、批次春茶-A；履历新增一条（含调拨人 taster 与时刻）。
6. 总表切到甲台服务端视图看不到春茶-A；切到乙台视图看得到。
7. 以未入册的「丙台」作目标（或源台）提交调拨，返回 400 且履历条数不变。
8. 直接对 `transfers` 执行 UPDATE / DELETE 被触发器拒绝（“调拨履历不可删改”）。
